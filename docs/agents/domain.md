# Domain documentation

This repository uses one domain context.
Domain documentation defines project terms and records durable design decisions.
An architecture decision record, or ADR, explains a design decision.

Before code exploration, read these documents if they exist:

- Read `../../GLOSSARY.md` for project terms.
- Read relevant ADRs under `../adr/`.
- Read the repository instructions in `../../AGENTS.md`.

If a glossary or ADR directory is absent, proceed without reporting its absence.
Create domain documents through `domain-modeling` only when terms or durable decisions require them.
Follow the repository requirements for authorization and document preservation.

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a needed term is absent, reconsider the term or note the gap for `domain-modeling`.
If a proposal conflicts with an ADR, name the ADR and explain the conflict.
